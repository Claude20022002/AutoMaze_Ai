# Architecture définitive du livrable 1 – AutoMaze AI

Périmètre fonctionnel clarifié

Intitulé : Classification d'objets routiers par Machine Learning pour les véhicules autonomes

À partir de tes choix, nous pouvons maintenant fixer l'architecture du projet et celle du rapport Go/No-Go.

Le principe fondamental est le suivant :

- Le simulateur connaît les positions et les coordonnées des objets dans son environnement.
- Le modèle de Machine Learning analyse les images fournies par la caméra et détermine la nature des objets.
- Le système de décision combine la classe prédite et les informations de position fournies par le simulateur.
- Le planificateur calcule le chemin vers la destination et le recalcule si un obstacle rend le trajet impraticable.
- Le contrôleur applique les décisions au véhicule virtuel : continuer, ralentir, s'arrêter ou changer de direction.

Ainsi, le simulateur sert à démontrer l'intégration du modèle dans un scénario de conduite autonome. Il ne constitue pas le sujet principal du projet.

Périmètre du projet

Travail ML

Données, extraction, entraînement, comparaison et classification

Intégration

Simulation, localisation, planification et contrôle

Le travail ML reste le cœur scientifique du projet ; l'intégration démontre son utilité dans un véhicule autonome virtuel.

Point technique à préciser dans le rapport : les coordonnées fournies par le simulateur servent à associer les objets aux prédictions du modèle. Il faudra définir comment cette association est réalisée (par exemple, identifiant de l'objet ou correspondance entre la position projetée dans l'image et les coordonnées du monde virtuel). Le simulateur ne doit pas communiquer directement la classe réelle au système de décision, sinon cela contournerait le modèle ML.

## 4. Fonctionnement détaillé des modules

Voici les éléments techniques à documenter dans le rapport, sans entrer dans la réalisation complète du simulateur.

### 4.1. Module de classification

Exemple de classes envisagées, à confirmer selon le dataset retenu :

- Cycliste

- Bus

### 4.2. Module de localisation et d'association

Le simulateur fournit une structure d'informations pour chaque objet présent dans l'environnement.

Exemple conceptuel :

| Identifiant | Coordonnées virtuelles | Classe prédite |
| ----------- | ---------------------- | -------------- |
| OBJ-01      | (12, 5)                | Voiture        |
| OBJ-02      | (18, 9)                | Piéton         |
| OBJ-03      | (22, 4)                | Camion         |

L'identifiant ou la correspondance spatiale permet de rattacher la prédiction visuelle à l'objet du monde virtuel.

Il faut bien séparer deux informations :

- Vérité terrain du simulateur : la classe réelle et les coordonnées, disponibles pour construire et vérifier les scénarios.
- Résultat de perception : la classe prédite par votre modèle ML.

Pour la prise de décision, on utilise la classe prédite et les coordonnées, et non la classe réelle cachée du simulateur. Cela permet de vérifier réellement l'apport du modèle.

### 4.3. Module de planification

L'environnement est représenté sous forme de graphe :

- Les nœuds représentent les positions ou intersections accessibles.
- Les arêtes représentent les chemins possibles.
- Les poids représentent les coûts de déplacement.
- Les obstacles rendent certaines arêtes impraticables ou modifient leur coût, selon la stratégie retenue.

L'algorithme de Dijkstra calcule un chemin de coût minimal entre le départ et la destination.

Attention : le chemin le plus court n'est pas toujours le chemin le plus rapide ou le plus sûr. Pour votre démonstration, vous pouvez commencer par des distances comme coûts, puis prévoir des pénalités si certains passages sont moins favorables.

### 4.4. Module de décision

Le système de décision traduit les informations de perception et de planification en actions.

| État de l'environnement           | Décision possible                          |
| --------------------------------- | ------------------------------------------ |
| Aucun obstacle sur la trajectoire | Continuer                                  |
| Obstacle proche mais contournable | Ralentir et préparer le contournement      |
| Obstacle bloquant                 | S'arrêter et demander un nouvel itinéraire |
| Nouveau chemin disponible         | Changer de direction                       |
| Aucun chemin possible             | Rester arrêté                              |
| Voie dégagée                      | Reprendre le déplacement                   |

La nature de l'objet peut influencer la règle de décision, mais elle ne suffit pas à elle seule. Il faut également prendre en compte la position, la distance, la trajectoire et la vitesse relative si elles sont disponibles.

### 4.5. Module de contrôle

Il reçoit les actions décidées et commande le véhicule virtuel :

- Accélération.
- Décélération.
- Freinage.
- Arrêt.
- Direction gauche ou droite.
- Reprise du déplacement.

Il n'est pas nécessaire de développer un système de conduite physique réaliste dès le livrable 1. Une première logique de contrôle simplifiée suffit pour établir la faisabilité.

## 8. Points techniques à verrouiller dans le rapport

Il reste quatre décisions méthodologiques à expliciter pour éviter les ambiguïtés pendant la réalisation.

1\. Classification et localisation : le classifieur reçoit une image d'objet isolé ou une région d'image déjà identifiée. Le simulateur fournit les coordonnées et permet d'associer la prédiction à l'objet correspondant. Il ne faut pas présenter le classifieur comme un détecteur d'objets.

2\. Données d'entraînement : les images utilisées pour entraîner le modèle doivent être compatibles avec les objets et les classes rencontrés dans le simulateur. Il faudra vérifier les différences de rendu entre les images du dataset et les images virtuelles.

3\. Décision et sécurité : un objet classé comme piéton ne doit pas automatiquement provoquer la même décision dans toutes les situations. La distance, la position par rapport à la trajectoire et les règles de sécurité doivent également intervenir.

4\. Dijkstra et comportement : Dijkstra détermine le chemin optimal dans le graphe. Le système de décision et le contrôleur déterminent comment le véhicule se comporte pour suivre ce chemin.
